# Events, execution, and workflow APIs

`@xonava/core/events` exposes event/envelope/version/consumer registries plus audit, idempotency, inbox/outbox, and lease contracts. `@xonava/core/execution` exposes job/schedule registries, retry, progress, dispatch, and fingerprints. `@xonava/core/workflow` exposes definitions, registry, state machine, context, dispatcher, errors, version, and store.

Register versioned definitions before dispatch. Store implementations come from certified adapters. Handle stale claim/version errors as concurrency outcomes, not generic retries. Workflow durable values are bounded; use `defineWorkflow` and `createWorkflowRegistry`, then dispatch only with a fenced `WorkflowStore`. Workflow steps receive `executionSignal`, `deadline`, and `assertLease`; observe cancellation and re-fence immediately before external effects. `dispatchWorkflows` defaults to a 30-second step timeout (hard maximum five minutes), serializes lease renewal, and bounds claim batches. Do not perform non-idempotent external work under an assumption of exactly-once delivery.
